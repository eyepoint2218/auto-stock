# 인스타툰 릴스 만들기

이 환경에서는 **그림을 직접 생성할 수 없다.** 그림은 사용자가 ChatGPT로 그리고, 나머지(콘티·프롬프트·글·조립·업로드)를 전부 이 스킬이 맡는다.

**기본은 "한번에 제작"이다 (사용자 요청).** 사용자가 할 일은 두 번뿐: ① 프롬프트 1개를 ChatGPT에 붙여 6컷 한 장을 받는다 ② 그 한 장을 올린다. 단계마다 확인을 묻지 않는다.

```
주제 → [1단계] 콘티 + "6컷 한 장" 프롬프트 1개 → (사용자: 그림 한 장) → [2단계] 자르기·조립·미리보기·검사까지 한 번에 → [3단계] 업로드(요청 시)
```

## 0. 원칙
- **채널 정하기:** 영화·드라마 보는 일상 툰은 스크린데일리(기본), AI·학교·직장 같은 사회 풍자 툰은 **팝콘툰** → post.yml 에 `channel: toon` (마지막 장·해시태그·업로드 계정이 팝콘툰 것으로 바뀜). 팝콘툰 게시물의 `hashtags` 에는 `인스타툰`을 넣지 않는다 (기본 해시태그에 있음).
- `CLAUDE.md` 후킹 규칙을 모두 지킨다 (제목 20자 이하, 말풍선 10자 이하, 이모지 금지, 인사 금지, CTA 하나).
- **사실만.** 작품명·회차·출연을 넣으면 확인된 것만 쓴다. 확인 못 하면 작품을 빼고 일반 상황으로 쓴다. 작품을 약속하는 문구("이 드라마")를 쓰면 반드시 끝에서 작품명을 밝힌다.
- **실존 인물은 그리지 않는다** (초상권). 배우가 꼭 필요하면 그 장만 공식 스틸(`tmdb: "movie/ID"`)을 쓴다.
- 초안은 `drafts/toon_<영문슬러그>/`에 `draft: true`로 만든다. `queue/`에는 사용자가 올려 달라고 할 때만 옮긴다.
- 다른 계정의 캐릭터·문구를 베끼지 않는다.

## 1단계. 주제 → 콘티 + 프롬프트

### 1-1. 구성 (고정: 6컷, 릴스 약 18초)
| 컷 | 역할 | 렌더 위치 |
|---|---|---|
| p1 | 후킹 (상황 시작) | 표지 `cover_style: toon` |
| p2 | 전개 | items[1] |
| p3 | 사건·반전 | items[2] |
| p4 | 결과 (가장 공감 가는 장면) | items[3] |
| p5 | 여운·반전 한 번 더 | items[4] |
| p6 | 캐릭터가 정면을 보고 질문 → 댓글 유도 | items[5] |

- **위 상자(title)는 앞 장에서 이어지는 문장**으로 쓴다 ("분명 ~했는데" → "~에서" → "정신 차려보니" → "그런데"). 다음 장으로 넘길 이유를 만든다.
- 아래 상자(desc)는 그 장의 결론. 위 22자, 아래 30자 이하.
- 말풍선은 캐릭터의 속마음 한 마디, 10자 이하 ("출근 어떡해ㅠ").
- 표지 제목은 후킹 유형을 섞는다 (상황 공감 + 숫자/시간 "새벽 2시"). `queue/`의 이번 주 다른 게시물과 같은 유형을 연달아 쓰지 않는다.
- CTA는 p6 댓글 하나 (`outro_question`도 같은 질문).

### 1-2. 이미지 프롬프트 (기본: 6컷 한 장)
채팅에는 **아래 "6컷 한 장" 프롬프트 1개만** 코드 블록으로 준다. 컷별 장면(1-2 아래 요령대로 2~3문장)을 1~6번에 채운다.

```
첨부한 캐릭터와 똑같은 얼굴·머리·안경·옷·그림체로 인스타툰 6컷을 한 장에 그려줘.

[캐릭터 고정]
20대 후반 여성, 짧은 검은 단발 + 앞머리, 동그란 검은 뿔테 안경, 빨간 후드티, 청바지, 흰 양말·운동화, 2.5등신, 큰 눈, 볼터치.
깔끔한 검은 외곽선, 부드러운 파스텔 채색, 한국 인스타툰 그림체.

[칸 구성]
세로 2:3 이미지, 2열 x 3행 격자로 정사각형 칸 6개. 칸 사이는 굵은 흰 여백으로 확실히 나눠.
읽는 순서: 1행 왼쪽→오른쪽, 2행 왼쪽→오른쪽, 3행 왼쪽→오른쪽.
6칸 모두 같은 캐릭터, 같은 옷, 같은 그림체.

1번 칸: (장면)
2번 칸: (장면)
3번 칸: (장면)
4번 칸: (장면)
5번 칸: (장면)
6번 칸: (장면)

[규칙]
- 이미지 안에 글자, 숫자, 말풍선, 효과음 글씨를 절대 넣지 마
- 칸마다 위쪽 모서리 한 곳은 비워 둬 (말풍선 자리)
- 배경은 단순하게
```

컷 하나만 다시 그려야 할 때를 위해 `PROMPTS.md`에는 아래 컷별 프롬프트 6개도 같이 적어 둔다 (채팅에는 붙이지 않는다).
컷별 프롬프트는 아래 틀을 **통째로 복사해 쓸 수 있게** 완성해서 준다. `[장면]`만 장마다 바꾸고, 캐릭터 블록·규칙은 그대로 둔다.

```
첨부한 캐릭터와 똑같은 얼굴·머리·안경·옷·그림체로 인스타툰 한 컷을 그려줘.

[캐릭터 고정]
20대 후반 여성, 짧은 검은 단발 + 앞머리, 동그란 검은 뿔테 안경, 빨간 후드티, 청바지, 흰 양말·운동화, 2.5등신, 큰 눈, 볼터치.
깔끔한 검은 외곽선, 부드러운 파스텔 채색, 한국 인스타툰 그림체.

[장면]
(장소, 시간대·빛, 캐릭터 자세, 표정, 손에 든 소품, 배경 소품을 구체적으로 3~4문장)

[규칙]
- 정사각형 1:1
- 외곽선 깔끔하게, 배경은 단순하게
- 이미지 안에 글자, 숫자, 말풍선, 효과음 글씨를 절대 넣지 마
- 위아래 여백을 조금 넉넉하게
```
장면 쓰는 요령:
- 시간 흐름을 **빛·소품으로** 보여준다 (시계 바늘, 창밖 밤→아침 햇살, 빈 팝콘 통, 울리는 휴대폰). 글이 없어도 이야기가 이해되게 한다.
- 표정은 캐릭터 시트의 6개에서 고른다: 기본 웃음, 놀람, 울먹, 감동, 졸림, 짜증.
- 장마다 구도를 바꾼다 (전신 → 이불 속 → 화면 앞 클로즈업 → 전신 → 다른 장소 → 정면 상반신).
- 말풍선이 들어갈 **빈 공간**(위쪽 모서리)을 남기도록 쓴다.
- 사용자에게 안내: 기준 이미지 `assets/brand/toon_character.jpg`를 매번 첨부하고 같은 대화창에서 이어서 생성. 얼굴이 바뀌면 "첨부 이미지와 같은 캐릭터로 다시. 안경, 앞머리, 빨간 후드티를 똑같이".

### 1-3. 결과물
1. `drafts/toon_<slug>/PROMPTS.md`: 콘티 표(컷·위 상자·아래 상자·말풍선) + 완성된 프롬프트 6개.
2. `drafts/toon_<slug>/post.yml`: 아래 템플릿으로, `image: img/p1.jpg`~`p6.jpg`를 미리 적어 둔다.
3. 채팅에는 콘티 표 + "6컷 한 장" 프롬프트 1개만 코드 블록으로 붙인다. 마지막에 "ChatGPT에 캐릭터 이미지를 첨부해 붙여 넣고, 나온 그림 한 장을 올려 주세요" 한 줄. 커밋·푸시까지 이 단계에서 끝낸다.

```yaml
# 인스타툰 릴스: <주제> (그림: 채널 캐릭터, ChatGPT 이미지 생성)
publish_at: "YYYY-MM-DD 18:00"
format: reel
draft: true
label: MOOD
cover_style: toon
cover_image: img/p1.jpg
title: "<표지 제목, 20자 이하, 2~3줄>"
subtitle: "<표지 아래 상자>"
bubble: "<표지 말풍선>"
items:
  - type: toon
    title: "<위 상자>"
    desc: "<아래 상자>"
    image: img/p2.jpg
    bubble: "<말풍선>"
  # ... p3~p6 같은 형식
outro_question: "<p6 질문과 같게>"
caption: |
  <상황 요약 2줄, 이모지 없이>

  <p6 질문> 댓글로 알려주세요.
hashtags: [인스타툰, <주제 키워드 2개>]
```

## 2단계. 그림 받기 → 조립 (중간에 묻지 않고 끝까지)
사용자가 그림을 올리면 아래를 **한 번에** 끝내고 결과만 보여준다.

1. 그림 저장:
   - **6컷 한 장**이면 `python -m screendaily toon-split <그림 경로> toon_<slug> --drafts` → `img/p1~p6.jpg`(칸 사이 여백을 찾아 자르고 테두리를 걷어 냄). 잘린 6장을 이어 붙여 직접 보고, 칸이 어긋났으면 수동으로 다시 자른다.
   - **6장 따로**면 (보통 업로드 순서 = p1~p6, 헷갈리면 장면 내용으로 맞춘다) 각각 `drafts/toon_<slug>/img/pN.jpg`로 저장 (PIL로 RGB 변환, quality 92).
2. **그림을 직접 보고 말풍선 위치를 정한다.** `bubble_pos`: `left`/`right` + `top`/`bottom` (예: `left-top`). 얼굴, 그리고 이야기에 필요한 소품(울리는 폰, 시계 등)을 가리지 않는 빈 곳으로.
3. 표지 사진 위치가 어긋나면 `cover_focus: "0.5,0.45"`로 조정.
4. 미리보기: `python -m screendaily preview --drafts toon_<slug> --force`
5. 검사: `python -m screendaily lint --drafts toon_<slug>`.
6. `out/01~07.jpg`를 한 장으로 이어 붙여(4열) 직접 확인 → 말풍선이 얼굴을 가리거나 글이 넘치면 고친 뒤 사용자에게 `SendUserFile`로 보여준다.
7. 그림이 일부만 왔으면 있는 것까지 조립하고, 빠진 컷의 프롬프트를 다시 안내한다.

그림 품질 확인 포인트: 캐릭터(안경·앞머리·빨간 후드)가 장마다 같은지, 이미지 안에 글자가 들어갔는지(있으면 다시 생성 요청), 시간 흐름이 보이는지.

8. 커밋·푸시까지 하고, 미리보기 한 장 + "올릴까요? (시간)" 한 줄로 끝낸다. 사용자가 처음부터 "업로드까지"라고 했으면 바로 3단계로 이어간다.

## 3단계. 업로드 (사용자가 요청할 때만)
1. 시간 정하기: 사용자가 말하지 않았으면 물어본다. 스크린데일리는 평일 18:00이 기본이고, `queue/`에서 빈 자리를 찾는다 (폴더 이름과 실제 `publish_at`이 다를 수 있으니 `publish_at` 기준). "지금 바로"면 현재 한국 시간(`TZ=Asia/Seoul date`)으로 적는다.
2. `queue/<YYYY-MM-DD_HHMM>/`로 `post.yml` + `img/`를 복사하고, `draft: true`를 지우고 `publish_at`을 맞춘다. 원본 시트 같은 안 쓰는 이미지는 넣지 않는다 (미리보기 때 자동 삭제됨).
3. `python -m screendaily lint <폴더>` → 경고가 없을 때까지 고친다. `python -m screendaily preview <폴더> --force`로 `reel.mp4`를 만들고 길이(약 18초)를 확인한다.
4. 자동 업로드는 **main의 `queue/`만** 본다. main에 커밋·푸시한다. 미리보기 워크플로 커밋과 충돌하면 `git fetch` 후 merge하고, `out/` 충돌은 새로 렌더한 쪽(ours)으로 맞춘다.
5. 업로드 워크플로는 매시 7분·37분에 돈다. `origin/main`에 `post: <폴더> 업로드 완료` 커밋이 생기는지 백그라운드로 확인하고 결과를 알린다.
6. 배경음악: `config.yml`의 `reel.bgm`이 비어 있으면 무음 릴스가 된다고 알려 준다 (저작권 없는 음원만).
