# 역사그램 제작 지침 (@historygram.kr)

역사 속 잘 알려지지 않은 실화와 인물을 **8장 캐러셀**(스토리 5장 + 퀴즈 + 인물 공개 + 팔로우)로 소개한다. 기준 예시: `episodes/ep02_kimjeomdong`.
**역사적 사실은 정확하게, 이야기는 흥미롭게, 이미지는 자연스럽게.** 마지막 장까지 넘겨야 정체를 알 수 있게.

## 매일 한 명 흐름
1. **인물 고르기**: `python -m historygram next` → `people.yml` 맨 위 미완료 인물. 사료로 확인이 어려우면 건너뛰고 이유를 적는다.
2. **사실 확인**: 웹 검색으로 실록·문집·백과(한국민족문화대백과, 국사편찬위원회 등)를 대조. 확인된 것만 쓴다.
3. **회차 만들기**: `python -m historygram new N 이름 slug` → `episodes/epNN_slug/episode.yml` 채우기.
4. **검사**: `python -m historygram check epNN` 경고 0개.
5. **미리보기**: `python -m historygram render epNN` → 1·6·8장 완성, 2~5·7장(삽화 자리)은 배치 미리보기(`*_layout.png`).
6. **GPT 프롬프트**: `python -m historygram prompt epNN` → 운영자에게 코드 블록 하나로 그대로 전달(한 번에 복붙).
7. **삽화 받기**: 운영자가 GPT 그림 5장을 보내면 장면을 보고 순서를 맞춰 `ingest epNN 그림1 그림2 그림3 그림4 그림5`(스토리 2·3·3.5·4장 + 인물 공개) → `render epNN`. 한 장만 다시 받으면 `ingest epNN 3.5=그림.png`.
8. **검수 후 전달**: 한글 오탈자, 인물 일관성, 복식 고증, 글자 잘림·겹침을 화면으로 확인 → `out/preview.png` 보여주고 `out/epNN_slug.zip`(PNG 8장 + caption.txt) 전달.
9. `people.yml` 에 done: true, ep 번호 기록. `status` 갱신.

## 캐러셀 8장: 업적으로 이어지는 한 줄기 (기준 예시 EP.02 김점동)
| 출력 장 | episode.yml 키 | 역할 | 예시(EP.02) | 글자 위치 |
|---|---|---|---|---|
| 1 | slides.1 | 당시의 문제·상황. 검은 배경 + 글자만 | 아파도 참아야 했던 [조선의 여인들] 남자 의사 앞에선 몸을 보일 수 없었죠. | 가운데 |
| 2 | slides.2 | 질문: 이 문제를 누가, 어떻게? | 그런 여인들에게 누가 [손]을 내밀 수 있었을까요? | 아래 |
| 3 | slides.3 | 계기와 준비(결심·배움·노력) | 수술을 지켜보던 소녀는 바다를 건너 [의학]을 배웠어요. | 아래 |
| 4 | slides.3.5 | 전환점(돌아옴·떠남·결단 등 업적 직전의 행동) | 서양 의학을 배우고 다시 [조선]으로 돌아왔어요. | 아래 |
| 5 | slides.4 | 업적: **무엇을 했는지**가 문구만으로 드러나게 | 조선 여성 최초의 [의사]로서 여인들을 돌봤어요. | 위 |
| 6 | (자동) | 퀴즈: 그는/그녀는 [누구]일까요? (`quiz:` 로 변경 가능) | 그녀는 [누구]일까요? | 가운데 |
| 7 | slides.5 | 인물 공개: 정면 얼굴, 이름, 생몰연도, 한 줄 업적 | 김점동 (1876~1910) 아픈 여인들 곁을 지킨 한국 최초의 여성 의사 | 아래 |
| 8 | (자동) | 공용 팔로우 카드 | | - |

- **장과 장이 원인→결과로 이어져야 한다.** 앞 장의 마지막 말을 다음 장이 받는다(문제 → 누가? → 배움 → 돌아옴 → 업적). 순서가 실제 연도 순서와 어긋나면 안 된다(예: 의사가 된 건 귀국 전 → 업적 장은 "의사로서").
- 업적과 이어지지 않는 곁가지 사연(가족의 희생 등)은 카드에 넣지 않고 필요하면 게시글에 한 줄로만.
- 전환점이 마땅치 않은 인물은 3.5를 빼고 7장으로 만들어도 된다. 더 넣을 땐 소수 키(3.7 등)를 쓰고 삽화는 `art_3_7.jpg`. 출력 번호는 자동으로 밀린다.
- 퀴즈 장까지는 이름을 쓰지 않는다. 게시글의 '몇 장' 표기는 출력 번호(인물 공개 = 7장) 기준. 스토리 장 삽화는 뒷모습·손·실루엣으로 정체를 숨긴다.
- **말투는 부드러운 이야기체.** 카드는 해요체·여운 있는 말끝("~했죠", "~했어요", "~일까요?"), "~했다" 같은 딱딱한 서술형과 '여성' 같은 보고서 말투 피하기(여인·소녀처럼 장면이 그려지는 말). 게시글도 같은 말투.
- **드라마 연계 특집:** people.yml 의 hook 에 '(드라마 문무 인물)'이 있는 회차는 episode.yml 맨 위에 `badge: 문무 특집` 을 넣는다(1장 위쪽 가운데 노란 테두리 배지). 방송사 로고·포스터는 쓰지 않는다. 방영이 끝나면 넣지 않는다.
- **삼국지 인물:** 표지 배지는 넣지 않고, 인물 공개 장 이름 위에 `reveal_badge: 삼국지` 를 넣는다. 그림 복식은 3세기 후한·삼국 시대(명·청·일본풍 금지).
- **시험 빈출 인물:** people.yml 의 hook 에 '(시험 빈출)'이 있는 회차는 `reveal_badge: 시험 빈출`(인물 공개 장 이름 위)과 `exam_keywords: [키워드, ...]`(4~6개, 한능검·교과서에 나오는 용어. 게시글 본문 끝에 '[시험에 나오는 키워드]' 한 줄로 자동으로 붙음)를 넣는다. 카드 흐름은 평소처럼 이야기체로, 암기 카드처럼 만들지 않는다.
- 노란색 강조는 장마다 핵심 단어 하나(`[대괄호]`).
- 줄당 글자는 짧게(1장 8자 안팎, 스토리 장 10자 안팎). 넘치면 자동으로 줄어들지만 60px 아래면 경고.

## 사실과 연출
- 직접 발언이 확인되지 않은 대사는 재구성 대사로 취급하고, 1장 `note: 재구성 대사` 또는 게시글에 밝힌다.
- 사료와 다른 장면은 해당 장 `note: 재구성 연출`.
- 생전 초상이 없으면 인물 공개 장(slides.5) `note: 상상화`. 후대 영정을 생전 초상처럼 말하지 않는다.
- 사료에 없는 대화·사건을 사실처럼 만들지 않는다. `sources`, `staging` 을 반드시 채운다.
- 통설과 사실이 다르면(예: 씨 없는 수박) 그 자체를 후킹으로 쓰되 근거를 게시글에 적는다.

## 게시글
- **첫 줄은 후킹 + 검색어.** '더 보기' 전에 보이는 125자 안에 질문·반전으로 끝내고, 사람들이 검색할 말(예: '조선 여성 최초의 의사')을 자연스럽게 넣는다(인사·자기소개 금지).
- `search_keywords`: 이름·별칭·업적·관련 인물·장소·시대 8~12개. 게시글 끝 채널 소개 아래 한 줄로 자동으로 붙는다(해시태그 5개와 별개).
- 그다음 흐름: 배경 → 사건 → 업적과 오늘의 의미 → 독자에게 묻는 문장.
- 업적은 구체적으로: 누구를 위해 무엇을 했고 왜 중요했는지(당시 상황) 두세 문장. 숫자는 교차 확인된 것만.
- 과도한 감탄사, AI 특유의 상투 표현, 이모지 금지. 해시태그 최대 5개(#역사그램 포함).
- 채널 소개(`channel_intro.txt`)와 해시태그는 자동으로 붙는다.
